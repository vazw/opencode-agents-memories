# mem-profile

**Purpose:** passive user-profile learning: prompt cold buffer, extraction, confidence/decay, AI cleanup. W3.1 lands the US 3.1 **locking half**: the prompt store's claim state machine, the cross-process `cold-buffer.json` snapshot, the coordination-DB learning lock, the learning-service shell, and the pure idle-debounce scheduler.

**Upstream contract:** `example/opencode-mem/src/services/user-prompt/*`, `src/services/user-profile/*`, `src/services/user-memory-learning.ts` (read-only reference; D-V1 ported upstream's actual storage — Turso DBs + a JSON snapshot — over the PRD's superseded JSONL hypothesis).

## Ubiquitous language

| Term | Meaning |
|---|---|
| **cold buffer** | `cold-buffer.json` in the storage root: observations seen while the embedding boundary was cold, kept for a later warm merge. |
| **snapshot** | The whole cold-buffer file parsed as one strict JSON object: `{ "<profileId>": bucket }`. Never line-oriented. |
| **bucket** | One profile's buffered observations: `{ preferences, patterns, workflows }` (missing category ⇒ empty array). The unattributed bucket key is `__unattributed__`. |
| **merge round** | One `ProfileStore::merge_profile_data` call: strict reload of the snapshot → optional warm drain → dedup/append → persist. The loaded map is fixed for the round. |
| **claim** | The `user_prompts.captured` transition `0 → 2` (`UPDATE … WHERE captured = 0`, true iff exactly one row changed). It marks a row as being captured without declaring it done. |
| **claim state machine** | `captured ∈ {0, 2, 1}`: `0` uncaptured, `2` claimed in flight, `1` captured. `release` is `2 → 0`; `mark` is `* → 1`; `1 → 2` / `1 → 0` are unrepresentable (their WHERE clauses no-op). |
| **owner token** | The per-acquire identity written into the coordination row (`{pid}-{unix_millis}-{counter}`). Release is `DELETE … WHERE owner_token = <token>`, so a stale release can never drop a newer owner's row. |
| **coordination DB** | `.profile-learning-coordination.db`: a standalone, **unencrypted** Turso database holding only the single `profile_learning_lock` row. One handle per operation; no transaction is held across an LLM round trip. |
| **identity triple** | `(pid, boot_id, starttime)` — what the lock records about its owner and compares on the next acquire. |
| **CAS reclaim** | `UPDATE … SET owner_token = <new> WHERE name = … AND owner_token = <old>`: the only way to take a conflicting row, and only after the old owner is *provably* dead. Exactly one competitor can win. |
| **dead (definitively)** | Boot-id mismatch (previous boot), OR same-kind starttime mismatch (PID reuse), OR `/proc` absent + `kill(pid, 0) == ESRCH`. `EPERM` and any unparseable/cross-kind identity mean **not dead**. No TTL, no mtime rule. |
| **fail-closed** | Unknown on-disk/coordination state refuses the operation instead of guessing: an unreadable/corrupt snapshot is never overwritten, a malformed lock row is never unlinked, a live-but-unverifiable owner is never stolen. |
| **warm drain** | A merge with a warmed-up embedding boundary splices that profile's buffered observations into the incoming batch and clears the bucket (persisted immediately). Other profiles' buckets are untouched. |
| **short write** | A `write` that forwards fewer bytes than requested. The save loop tolerates any positive forward progress and errors `write stalled after {N} bytes` on `n <= 0`; the payload is UTF-8 **bytes**, never string offsets. |
| **atomic publish** | The tmp file (`{cold-buffer.json}.{token}.tmp`, `create_new`, 0600) is fsynced, closed and renamed over the target. The rename is the only publish; any failure unlinks the tmp file and leaves the prior snapshot bytes intact. |
| **changelog** | A `user_profile_changelogs` row recording `(version, change_type, change_summary, profile_data_snapshot)`; `create` on profile creation, `update` on every successful optimistic-version write (retention = newest `changelog_retention_count` versions). |
| **debounce** | The `session.idle` gate: a per-session 10 000 ms window (`DEBOUNCE_MS`) before capture + learning run. A re-idle replaces the deadline; internal sessions and a disabled auto-capture produce no work. |
| **worker fixture** | An upstream Bun worker script translated to a `fixture_child_entry` subprocess (`#[test] #[ignore]`, self re-exec via `current_exe()`); all handshakes are barrier files with bounded waits, never sleeps. |
| **WriteFaults** | The fixture-only write seam on `cold_buffer::save_snapshot_with`: `chunk_limit` (bytes per write), `zero_at` (a 0-byte write), `fail_at` (a simulated mid-payload EIO). Production always passes the all-`None` default. |
| **Language** | The resolved output language of a profile analysis, carried as an ISO 639-1 code (`language_detector::Language`). `whatlang` reports ISO 639-3, so the 69-row `LANGUAGES` table is the bridging contract; `Language::name()` is the English name the prompts embed. |
| **language resolution** | Whether the model is told to write in the user's language or a configured one: `autoCaptureLanguage` `auto`/unset ⇒ `detect_language` over the **joined raw prompt contents** (`"\n\n"`), an explicit code ⇒ that language. Resolution happens exactly once per round, after select and before truncation/scaffold (detecting on the scaffold would bias short non-English batches to English). |
| **prompt mode (json/tool)** | Which transport serves the same analysis: `PromptMode::Json` (OpenCode structured output — the system prompt asks for the profile JSON object and must not mention tools) vs `PromptMode::Tool` (external API tool call — the system prompt requires the `update_user_profile` tool). Both prompts are pre-built by the round into `AnalysisContext`, so a gateway cannot pick the wrong one. |
| **provider-failure contract** | An unrecoverable provider fault returns `Err(ProfileError::Analysis(<failing provider's verbatim message>))` with **zero** profile writes, **zero** `mark_many`, the lock released and the flag reset — never `NotReady`, never a synthesized `External API not configured`. Only `AnalysisError::Provider` is fallback-eligible, and only when `external_configured()`; `Storage`/`Parse` propagate. |
| **per-prompt cap** | `MAX_PROMPT_CHARS` (4096): each prompt's content is cut to its first 4096 **chars** (char-safe, no marker) before the numbered list is assembled — upstream's "4096 chars before the LLM call". |
| **context cap** | The whole assembled analysis context is cut head-only to `max_context_chars` (`userProfileMaxContextBytes`, default 32768) **chars**, then closed with `CONTEXT_TRUNCATION_MARKER` (upstream's `substring` + marker byte parity). The head+tail `mem_core` helper is deliberately not used — it would change upstream's profile behavior. |
| **trait type** | `validation::TraitType` (`Preference` / `Pattern` / `Workflow`): a synthetic id's prefix (`pref_` / `pat_` / `wf_`) selects the section; `TraitType::from_id_prefix` is the single id→section mapping reused by the cleanup apply loop and the rebuild. |
| **content bounds** | PRD R8: `TRAIT_MIN_CHARS = 3` / `TRAIT_MAX_CHARS = 500`, **characters** (`chars().count()`), both inclusive. Enforced inside `UserProfileValidator::validate` (so a provider payload is rejected before any merge) and exposed as `validate_trait_content`; no byte slicing anywhere. |
| **confidence EMA (α = 0.3)** | PRD lock, `decay::CONFIDENCE_EMA_ALPHA`: `sync_confidence` blends the stored confidence (prior) with the Beta estimator `alpha/(alpha+beta)` (observation) as `α·observation + (1−α)·prior`, then applies the decay factor. Deliberately **not** idempotent — repeated derivation drifts toward the estimator, which is why the write path is the interval-gated sweep. |
| **half-life decay (30-day base)** | PRD lock, `decay::HALF_LIFE_DAYS = 30`: `decay_factor(age, 30, frequency) = exp(−ln2 · max(0, age − 30 d) / halfLife)` with upstream's frequency scaling `halfLife = 30 d · (1 + log2(1 + freq))` (frequency 1 ⇒ a 60-day effective half-life). |
| **lazy decay on read** | `ProfileStore::decay_in_memory(data, now)`: per item `lazy_migrate_alpha` → default `last_seen` / `evidence` → re-derive confidence → drop when `decay::is_stale` (age > `stale_days` **and** evidence count < `min_evidence_for_retention`). The clock is the `now` argument — no wall-clock read. |
| **daily decay sweep** | `ProfileStore::sweep_decay_daily(now)`: the **persisted** sweep over every active profile, gated by `decay::sweep_is_due` (24 h) and written through `update_profile` with `Decay sweep: confidence decayed`. **No production scheduler yet (R13):** the host lifecycle (`mem-bridge` W5.x / the composition root) is expected to call it on a daily tick. |
| **cleanup scope** | `incremental_cleanup::cleanup_scope(data, landed)`: the traits that landed in this round plus their `mem_core::dedup` neighbours (exact-key groups and `[0.65, 0.9)` conflict groups), restricted to the sections+categories the round touched — incremental, never a full-profile scan (R6). |
| **cleanup apply (scoped/auto-accept)** | `cleanup_apply::merge_cleanup_into_profile`: upstream's order — start from the cleaned data, restore rejected merges/removals from `old_profile_data`, then re-insert only the `include_ids` scope into `current_profile`. The automatic path auto-accepts every merge and removal inside the scope. |
| **contradiction merge** | Two same-category traits inside the dedup conflict band are handed to the provider as one merge group; the rebuilt leader keeps the original metadata and its confidence becomes the α = 0.3 EMA folded over the group's original confidences. Items outside the pair are carried verbatim (R7). |
| **cleanup interval gate** | `validation::should_run_automatic_profile_cleanup(previous, added, interval, enabled)`: floors `previous/interval` and `(previous+added)/interval`; a boundary crossing fires. A fractional or non-positive interval, or a disabled switch, never fires (upstream's `Number.isInteger` guard). |
| **profile erasure (B2′)** | 47.1-B2′: deleting a prompt invalidates every profile that could have been derived from it. One reusable two-table delete (`user_profile_changelogs` first, then `user_profiles`, then the cold-buffer bucket) reachable from two surfaces: `UserPromptManager::delete_prompt` (with an injected `ProfileEraser`) and `DELETE /api/user-profile` for prompt-free migrated roots. Erase **before** the prompt delete: if the erase fails the prompt survives so a retry re-fires the event (fail toward privacy). |
| **watermark (`last_analyzed_at`)** | The `user_profiles.last_analyzed_at` column: the newest prompt timestamp a profile is known to have digested. `create_profile` and `update_profile` both bind `now` to it (D-5), so every profile write moves it forward — older prompts therefore count as contributing. Unset/zero/negative ⇒ treated as "contributes" (fail toward erasure). |
| **contributing prompt** | A prompt whose `created_at` satisfies `could_have_contributed(watermark, created_at)` — `watermark <= 0` or `created_at <= watermark`. Deletion erases every profile for which the deleted prompt was contributing; the scan covers **all** `user_profiles` rows, not only `is_active = 1` (an inactive row still holds derived text). `created_at` that is unreadable / non-integer on an existing row counts as contributing (D-6). |
| **`<user_profile>` block** | `profile_context::render_profile_block`: the four frozen sections (`User Preferences:`, `User Patterns:`, `User Workflows:`, `Learning Paths:`) between `<user_profile>` and `</user_profile>`, exactly one blank line between two sections and none at the edges. Bounded by ITEM COUNT, never by the injector's byte budget; an all-empty profile renders `None`, never an empty wrapper. |
| **escape funnel** | `profile_context::escape_profile_text`: the ONE path from a profile-derived string into the block — collapse `\n`/`\r` to spaces, trim, then escape `&`, `<`, `>` in that order. The composition is load-bearing (D-44-2): escaping alone leaves `\nUser Workflows:` as a real line, so a description could forge a header even though it cannot close the block. |
| **render caps / policy** | `ProfileInjectPolicy { enabled, caps }` with `ProfileRenderCaps { preferences, patterns, workflows }`, built by `ProfileInjectPolicy::from_core`: the three `userProfileInject*` knobs are the caps and `maxProfileItems` is deliberately unread. Preferences: rank → `slice(0, 2N)` → recency blend (`confidence·0.7 + e^(−age_days/90)·0.3`) → one per category. Patterns: rank → one per category. Workflows: rank → top N. Learning paths: stored order, first three. |
