# mem-embed

**Purpose:** embedding pipeline: local ONNX (`ort`) + remote providers behind the `Embedder` seam producing `Vec<f32>`.

**Ubiquitous language:**

- **`Embedder` seam** — the one embedding interface: `warmup()` + `embed(text)` returning a boxed future of `Vec<f32>`; `Send + Sync` so it crosses the W1.3 concurrency boundary. `EmbedTask` (`Document` / `Query`) labels which prefix a caller wants. Divergence (recorded): the trait receives the FINAL text — task prefixes are applied by `EmbeddingService`/callers, not inside `embed()` (upstream applies them inside `embed()`; same observable service behavior).
- **Task prefix** — `search_document: ` / `search_query: ` (`NOMIC_DOCUMENT_PREFIX` / `NOMIC_QUERY_PREFIX`). Precedence: a custom prefix (`Some(..)`, including `""`) wins unconditionally; else `use_task_prefixes` selects the Nomic constant; else no prefix. `apply_task_prefix` never double-prefixes (text already starting with the prefix is returned unchanged).
- **dtype resolution** — which weights file to load. A declared `transformers.js_config.dtype` **string** in `config.json` wins; a **per-file object** declaration suppresses the probe (returns `None`); otherwise the first cached `onnx/model{suffix}.onnx` in the pinned `ONNX_DTYPE_VARIANTS` order (fp32 before q8 — the ordering is the contract). An explicit `LocalLoadOptions.dtype` always beats the probe; `Auto` behaves as unset (→ probe). Unknown declared strings fall through to the probe.
- **Model cache layout** — `{storagePath}/.cache/{model}/{config.json,tokenizer.json,onnx/model{suffix}.onnx}` (the transformers.js layout). The model id is a cache-relative subdirectory: empty / absolute / `..` ids are refused as `InvalidModelId` before any filesystem access.
- **Hub fetch** — minimal HF acquisition: `resolve/main` URLs, reqwest's default redirect following, no auth; every relative path validated (abs / `..` → `HubPathEscape`); each file fetched to `{file}.tmp` then `rename` (atomic — a failure leaves neither a partial destination nor a tmp); existing files never rewritten.
- **Pooling** — the parity surface: `mean` (mask-weighted, all-ones ≡ no mask) / `cls` (row 0) / `last_token` (last unmasked position), followed by f32 L2 normalization (zero norm stays zero). Shared by local and remote consumers via `pool_token_embeddings` / `l2_normalize_f32`.
- **Position limit** — the number of token positions the ONNX graph accepts, as *declared* by the cached `config.json` (root `max_position_embeddings` / `n_positions`, or the same keys under `text_config`; the **minimum** of those present wins). It is a property of the model, never of the text and never a constant. A present but malformed value (string, float, zero, negative) is treated as absent and reported as `embedding.position_limit_ignored`; `n_embd` is the hidden width and is never a position count.
- **Special tokens** — the ids the tokenizer's post-processor adds for a single sequence, measured behaviourally as `encode_text(tokenizer, "", usize::MAX).ids.len()` (2 for the fixture and nomic; 2 for e5 is INFERRED from the XLM-R template).
- **Cap tokens** — the number of token ids this build feeds the model, special tokens included: the unit `session.run` sees. Derived as `position limit − special tokens` (8,190 for nomic, 512 for e5), overridable by `embeddingMaxTokens` (refused, never clamped, above the declared limit). `usize::MAX` is the unbounded sentinel when nothing is declared and nothing is configured.
- **Head+tail truncation** — `head = cap/2`, `tail = cap − head`, the middle dropped; applied inside `encode_text` before `session.run`, with `attention_mask`/`type_ids` sliced by the same two ranges. The split is fixed, not configurable: the long rows are decision records whose head holds the subject and whose tail holds the ruling, and keeping the first and last ids preserves the template's boundary special tokens. `cap == 2` is the documented `[CLS][SEP]` degenerate pair (unreachable from configuration).
- **Where the cap lives in identity** — the configured `embeddingMaxTokens` is in the storage `EmbeddingIdentity` fingerprint (omitted when unset, so existing fingerprints are byte-identical); the *derived* cap is not. The model id is in the identity and `embedding.input_cap_resolved` logs the resolved cap and its source at every load, so a `config.json` whose position limit changes under the same model id is a provisioning event the operator owns. The cap is not in the embedding-service cache fingerprint either.
- **Remote retry policy** — per-attempt timeout 8000 ms, 3 attempts, LINEAR backoff `500 ms × attempt` (1× then 2×). Retryable = `429`, any `5xx`, `RemoteTimeout`, `RemoteNetwork`; invalid JSON / shape errors / other `4xx` fail fast on attempt 1. The API key travels only in the `Authorization: Bearer` header and never appears in an error.
- **FIFO embedding cache** — up to 100 entries (`MAX_CACHE_SIZE`) keyed by the prefixed input string; hit never reorders; eviction pops the first-inserted entry. The fingerprint (`model \0 pooling \0 queryPrefix \0 documentPrefix \0 prefixesFlag \0 dtype`) is the invalidation input set; a fingerprint change clears the cache.
- **Warmup gate** — sticky single-flight state machine `Cold → Warming → Ready | Failed` behind a `tokio::sync::Mutex`; concurrent cold callers share one `Embedder::warmup` (no `tokio::spawn`); a failure is sticky and named (`WarmupFailed`) and `warmup` is never re-run (upstream #184 "initializing forever").
- **Golden vectors** — `nomic-embed-text-v1` embeddings recorded from the upstream JS stack (transformers.js 4.3.1 + onnxruntime-node 1.30.0) into `tests/fixtures/nomic_goldens.json`; compared under `cos >= 0.9999` / `max-abs <= 1e-3` (ort 2.0.0-rc.14 vs onnxruntime-node kernel drift), network-free (`hub: None`), `#[ignore]`d in the hermetic suite.

Cross-links: these bullets are the pinned source of truth for every `Embedder`, prefix, dtype, cache-layout, hub-fetch, pooling, retry, cache, warmup and golden-vector term used by later waves (W1.3 consumes the `Embedder` seam; W2.1/mem-ai consume the service).
