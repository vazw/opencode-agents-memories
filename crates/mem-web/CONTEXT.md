# mem-web

**Purpose:** axum web explorer backend: upstream REST contract + new session-history endpoints.

**Ubiquitous language:**
- **Gate** — the ordered request middleware in front of every route and of the SPA fallback. Its order is fixed: (0) the Host allowlist, (1) the Origin gate, (2) the `OPTIONS` preflight short-circuit, (3) Basic auth, (4) the API-token / local-token gate for `/api/*`, (5) the route. The gate is the only place where a request is admitted or refused; a route never re-implements a gate rule.
- **Shell** — the SPA entry document (`index.html` of the built `web-ui/dist` bundle) as served by the web server. The shell is read per request (never cached by the server), served `text/html` with `Cache-Control: no-cache`, and carries the local token in an injected `<script>`.
- **SPA fallback** — serving the Shell for a client-routed path (a path whose last segment contains no `.`). It is GET-only, never applies to `/api/*`, never applies to a path containing `..`, and never masks a missing asset (a path with an extension answers 404, so a broken hashed-asset URL stays visible).
- **API token** — the operator-configured secret (`webServerApiToken`) that authorizes the `/api/*` surface. It travels as `Authorization: Bearer <token>` or as the `x-opencode-mem-token` header. An absent or empty API token means the surface is *not* token-gated; the local token is then the only way in.
- **Local token** — the per-installation secret generated by the server and injected into the Shell. It is a 32-byte random value, hex-encoded, stored in a `0600` file, and required on every `/api/*` path except `/api/health`. The comparison is byte-for-byte (`provided === token`): a missing local token authorizes nothing.
- **Basic auth** — the HTTP Basic gate for the Shell and the API surface, enabled only when a password is configured. The realm is `OpenCode Memory Explorer`; the password and username are trimmed; a blank password disables the gate; `/api/health` is always exempt.
- **Loopback host** — `127.0.0.1`, `localhost`, `::1`, `[::1]` or `0:0:0:0:0:0:0:1` (case-insensitive, trimmed). A non-loopback bind host must carry an API token or a Basic password, otherwise the server refuses to start.
- **Host allowlist** — the D-8 DNS-rebinding control: the set of names (`localhost`, `127.0.0.1`, `::1` and the configured bind host, each with an optional `:port`) a request's `Host` header may carry. It runs as the first gate check, before any response body can carry the local token. A missing, empty or malformed `Host` is refused (403). The comparison is name-based, not address-based: the port is parsed for well-formedness only and never compared. A wildcard bind (`0.0.0.0` / `::`) disables the allowlist — the operator has then opted into network exposure, which `assert_network_auth` already guards.
- **Fail-fast bind** — the server binds the configured host/port once and fails fast: a port conflict is an error (`AddrInUse`), never a port hop and never a takeover loop.
- **Health envelope** — the `{"success":true,"status":"ok","authEnabled":<bool>}` document served by `/api/health`. The health-probe rule (a 2xx whose body is not that envelope does not belong to this server) lives in the health module and is re-exported from the crate root.
- **Web server settings** — the `web_server_*` slice of the resolved configuration (`enabled`, `host`, `port`, `auth_password`, `auth_username`, `api_token`); the secrets are already resolved by mem-core, mem-web never re-resolves `env://` / `file://`.
