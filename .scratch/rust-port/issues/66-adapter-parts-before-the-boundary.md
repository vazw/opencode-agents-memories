## What, located precisely (at `8023dd8`)

- **`extractText`** — `plugin/src/plugin.js:549`. Its `if (typeof node.text === "string") return node.text;`
  branch returns a `{type:"text", text:"…", synthetic:true}` part's text, so the flag never reaches the
  boundary. The check must be an **early return** at the top of the function, not a filter on the join,
  because that branch returns before any join runs.
- **`parseIdleTranscript`'s `textResponses`** — `:898`–`:909`, where `:906` filters on
  `part.type === "text" && typeof part.text === "string"` and `:907` maps `part.text` directly. This surface
  never calls `extractText`; it needs the same flag check.
- The `userPrompt` path (`:892`) does call `extractText`, and `metadata.autoCaptureContext.userPrompt`
  (`:860`) is derived from it — so one early return covers both user-prompt assertions.

## Agent Brief

**Category:** bug

**Summary:** the adapter captures the port's own injected block as if the user had typed it.

**Current behaviour (verified at `8023dd8`):** `plugin/src/plugin.js` never reads `synthetic`. The flag
appears only where the port *creates* parts — `:692`, the pre-compaction ingest block pushed onto the
current user message's parts, and `compaction.js:112`, the outbound restore body. `extractText` returns a
synthetic part's text at its `typeof node.text` branch, and `parseIdleTranscript`'s `textResponses` reads
`part.text` without calling `extractText` at all. So if the host returns the pushed block inside
`session.messages()`, that block becomes the capture transcript and the summariser's prompt — the port
re-capturing its own memory content.

**Desired behaviour:** a part whose `synthetic` is `true` never contributes to `transcript`,
`metadata.autoCaptureContext.userPrompt`, or `textResponses`. `synthetic: false` parts are unaffected.

**Key interfaces:**

- `extractText` — one early return, `if (node && node.synthetic === true) return null;`, placed after the
  null/undefined check and **before** the `typeof node.text` branch. It must return `null`, not `""`: the
  array branch filters `null` out (`:554`), whereas `""` would survive as an element and the `join("\n")`
  would inject a blank line.
- `parseIdleTranscript` — add `&& part.synthetic !== true` to the `:906` text filter.
- The Rust precedent `part_is_synthetic` (`injection.rs:82`) supplies the semantics, not the code.
  `compaction.js` needs no change (outbound only), and no synthetic tool part is ever created, so
  `toolCalls` is out of scope — say so in the change rather than filtering it.

**Acceptance criteria:**

- [x] A test pushes a `synthetic: true` text part into the user message and asserts it reaches neither
      `transcript` nor `metadata.autoCaptureContext.userPrompt`.
- [x] A `synthetic: false` companion asserts the same text **does** reach both.
- [x] A case covering `textResponses`: a synthetic text part in an assistant message is absent from the
      collection, and a non-synthetic sibling is present.
- [x] The 52.5 verdict above is quoted in the change with its evidence path.
- [x] `cd plugin && node --test tests/*.test.mjs` is green, including `dist-sync` and `bundle-boundary`
      (the twin must be refreshed in the same commit).

**Out of scope:**

- `plugin/src/compaction.js` and the restore body — outbound, never read back.
- `toolCalls` — no synthetic tool part is created; state it, do not filter it.
- The Rust filter — 52's `part_is_synthetic` stays the store-side backstop and is not edited here.
- The V2 adapter (`plugin/src/v2/**`, frozen by issue 20) and `<memory_context>` (issue 50).
