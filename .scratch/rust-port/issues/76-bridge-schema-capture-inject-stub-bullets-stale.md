# 76 — docs · The `capture`/`inject` stub bullets are stale post-W5.3

Status: ready-for-agent — 2026-10-28 (rewrites the two bullets at `docs/bridge-schema.md:98-103`; docs-only)

> *This was generated by AI during triage.*

## What

`docs/bridge-schema.md:98-103` still describes `capture` and `inject` as the W5.1 stubs:

- the `capture` bullet (`:98-102`) says the ack "carries no durability guarantee in W5.1" and quotes
  the structured stderr line `{"level":"warn","component":"engine","event":"capture.stub_not_durable"}`;
- the `inject` bullet (`:103`) says `inject` answers
  `{"block":null,"memory_count":0,"tokens":0,"truncated":false,"handling_ms":<n>}`.

Both are false. Issue 21 landed the D-48 durable inbox for `capture`, and `inject` assembles a real
block. Issue 73 retensed the paragraph intro at `:96` and replaced only the `recall` bullet at
`:104`; these two bullets are byte-identical after that wave (recorded as RESIDUAL-1 of the issue 73
blueprint). This issue owns them.

## Mechanism (READ, cited by symbol)

- `crates/mem-bridge/src/engine.rs:304-362` — `call_capture`: the payload is validated, the inbox
  enqueue is **awaited** (durable) before the ack, the ack result is `{"accepted":true}`
  (`:361`), and a full inbox is `-32002` (`:302`; the code is pinned at
  `crates/mem-bridge/src/error_map.rs:70`). Degraded mode refuses writes with `-32001` and performs
  no inbox write (`:303`).
- `crates/mem-bridge/src/engine.rs:367-401` — `call_inject`: a real assembly runs; `empty_inject`
  is only the runtime-less branch (`:370`), not the whole method.
- `grep -rn 'capture.stub_not_durable' crates/` prints nothing: the event the bullet quotes was
  removed with the stub, and the sentence survives only at `docs/bridge-schema.md:101`.

## Desired behaviour

The two bullets describe what the engine does today: `capture` acks only after a durable enqueue and
can answer `-32002` on a full inbox; `inject` returns an assembled block (possibly empty for a
missing/blank `project_id` or an empty store, which is not the same claim as "a stub"). No code
changes.
