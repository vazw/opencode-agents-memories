## What to build

Background extraction of preferences/languages/conventions from prompts via the `AiProvider` into the profile store; the pure language detector runs alongside. Wave detail: `.scratch/rust-port/roadmap.md` §W3.2.

## Acceptance criteria

- [x] Behaviors ported: `user-profile-learning-language` — `autoCaptureLanguage` honored (`auto`/unset ⇒ detect on the joined **raw** prompt contents; an explicit ISO 639-1 code ⇒ override).
- [x] Behaviors ported: `user-profile-learning-prompt-mode` — the structured-output transport carries the JSON-object instruction with no `update_user_profile`/tool mention; the external tool-call transport carries the exact `Use the update_user_profile tool to save the {new|updated} profile.` sentence.
- [x] Behaviors ported: `user-profile-learning-error` — an unrecoverable provider failure returns the failing provider's message verbatim, writes no profile, marks no prompt, and leaves the lock/flag retryable.
- [x] Deferred to W5.4: `profile-tool-runtime` (see `## Deferred`).
- [x] Language detector is pure and independently tested.
- [x] Learning loop survives provider errors without losing buffered prompts.

## Deferred

`profile-tool-runtime` — **deferred to W5.4**. The upstream test drives `plugin.tool.memory.execute`, a tool-registration surface that does not exist before W5.4; W3.2 has no tool handler, and inventing one would be a new public API outside the learning round. Its six cases are carried in §W5.4's verification line so they cannot be lost: query rejection, blank content, private-content block, missing email, lock acquire/release, fail-closed contention.
