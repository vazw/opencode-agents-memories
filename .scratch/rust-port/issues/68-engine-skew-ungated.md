# 68 — Engine-version skew is ungated: a pre-compaction engine silently double-counts

Status: ready-for-agent — 2026-10-27 (re-verified at `f01ec63`: every premise holds; `plugin.js`/`engine.rs` citations shifted +1 after issue 22's merge. Brief under `## Agent Brief`.)

Issue 33 added `include.compaction` to the frozen `inject` request. ADR-0007 D-43 accepts an older
same-major engine (`engine.protocol >= wrapper.min_protocol`; the wrapper sends `protocol` and
`min_protocol` = `1.0.0` at `plugin/src/plugin.js:35-36`, the engine answers `1.0.0` at
`crates/mem-bridge/src/engine.rs:45` — both re-derived after issue 22's merge, which moved each by one),
and nothing in `hello` advertises whether the engine's
`inject` understands the new option. An engine built before issue 33 ignores `include.compaction` —
`fc41bbd`'s `include_options` reads only `recent_count` and `query` — and answers the compaction
request with the ordinary project chat block. The wrapper appends that block verbatim
(`plugin/src/plugin.js:717-718` at `6f8801b`: the `Array.isArray(output.context)` guard, then
`output.context.push(result.block)`), and the restore prompt carries it too.

That is the double-count AC 1 forbids — the injected `<project_agent_session_history>` block, plus the
episodic `## Recent sessions` / `## Related older sessions` legs, arriving a second time inside the
compaction context. It is **silent**: the engine answers successfully, the hook sees a non-empty block,
and no log records the version mismatch as one.

## Why it is reachable

`plugin/engine/<platform>-<arch>/` is gitignored and staged by `plugin/scripts/stage-engine.sh`. A
stale build left there beside a newer wrapper satisfies D-43's major-equal floor and is spawned. The
non-blocking argument is only that a shipped wrapper and engine come from one build; any hand-staged,
downgraded or partially updated install breaks that premise.

## What, located precisely

- **Advertise the capability.** D-43's `hello.result.capabilities` object is the additive home: emit
  `capabilities.compaction: true` from an engine that reads `include.compaction`.
- **Gate on it.** The wrapper records the capability from `hello` and passes `include.compaction` only
  when the engine advertised it; when absent it must **no-op** the two compaction hooks (no ingest
  context, no restore prompt, no toast) rather than fall through to a chat-block answer — the failure
  mode is a silent wrong answer, not a visible error.
- **The alternative** is raising `MIN_PROTOCOL` past the pre-compaction engine line, which refuses
  the old engine at the handshake (D-38 degradation) instead of silently mis-answering. Choose one;
  prefer the capability flag, because it does not shrink the accepted engine range.

## Cross-references

- **ADR-0007 D-43** — the `hello` handshake, the semver rule, and `capabilities` as the additive
  surface.
- **ADR-0017 "Known limitations"** — the same property, recorded where the compaction contract lives.

## Acceptance

- A wrapper test: a `hello` result without `capabilities.compaction` yields no compaction `inject`
  on the wire, and neither compaction hook changes `output.context` or calls `session.prompt`.
- An engine test: the capability is present in `hello` exactly when `include.compaction` is honoured.
- The two hooks' no-op is pinned, not assumed: an implementation that instead appends the chat block
  fails the first test.

## Blocked by / Blocks

- Blocked by: nothing — `plugin/` and `crates/mem-bridge/src/engine.rs` are both free to change after
  issue 33's merge.
- Blocks: nothing. Issue 33 ships correct behaviour against an engine from the same build.

## Agent Brief

> *This was generated by AI during triage.*

**Category:** bug
**Summary:** advertise the compaction capability in `hello`, and gate both compaction hooks on it, so a
pre-compaction engine can no longer answer the ingest request with the ordinary chat block.

**Current behaviour (verified at `f01ec63`):**
- The wrapper accepts any same-major engine `>= 1.0.0`: `protocolCompatible` (`plugin/src/plugin.js:305`) is
  same-major && `semverCompare(engineProtocol, MIN_PROTOCOL) >= 0`; the constants are `:35-36`.
- The engine's `handshake_result` advertises `fire_and_forget_capture`, `standalone`, `web` — and nothing
  else (`crates/mem-bridge/src/engine.rs:139`–`:147`).
- **The wrapper consumes no capability at all.** `grep capabilities plugin/src/*.js plugin/src/v2/*.js` finds
  only a comment in `v2/legacy-client.js`.
- `compactionParams` sends `include: { compaction: mode }` unconditionally (symbol: `compactionParams`,
  `plugin/src/plugin.js`), and the hook appends the answer with `output.context.push(result.block)`
  (`:719`).
- An engine built before issue 33 ignores `include.compaction` and returns the ordinary project chat block —
  the silent double count. Reachable through `plugin/engine/<platform>-<arch>/`, which is gitignored
  (`plugin/.gitignore:2: engine/`).
- ADR-0017 `## Known limitations` already records the defect (`docs/adr/0017-compaction-hook.md`, "Engine-version
  skew is ungated").

**Three constraints the issue body does not state, all measured:**
1. **The hello fixture is exact-after-mask.** `mask` walks every key (`crates/mem-bridge/tests/bridge_fixtures.rs:86`)
   and the hello test compares `mask(actual) == mask(expected)` (`:109`). Adding `capabilities.compaction`
   fails until `tests/fixtures/bridge/hello-response.json` is updated. That file is in this lane's carve.
2. **The shared stub would silence twelve compaction tests.** `plugin/tests/harness/bridge.mjs:122` advertises
   only the three capabilities. Once the wrapper gates on the flag, every compaction test using that stub
   stops exercising the hooks. Add `compaction: true` there; the negative case needs its own stub that
   withholds it.
3. **ADR-0017 D-4 says "no new response key, no fixture adjustment."** Narrowly, that is about the inject
   response — but read literally it forbids what this lane must do to `hello`. Amend its scope, or D-4 becomes
   false.

**One acceptance criterion cannot be tested as worded.** *"The capability is present in `hello` exactly when
`include.compaction` is honoured"* is an implication a single build cannot observe. Split it: assert the
capability is advertised, and keep the existing pair that proves the option is honoured
(`crates/mem-bridge/tests/compaction_capture_chain.rs:166` restore never returns the chat block; `:392`
without `include.compaction` is unchanged). The coupling is a contract; the two facts are the test.

**Desired behaviour:**
- The engine advertises `capabilities.compaction: true`; `hello-response.json` and the schema test move with it.
- The wrapper records the capabilities at the handshake, beside the existing protocol state.
- When `capabilities.compaction` is absent (or `capabilities` is absent), **both** compaction hooks no-op:
  no `inject` carrying `include.compaction` on the wire, no `output.context` change, no `session.prompt`, no
  toast — and one structured log line naming the version mismatch, so it is no longer silent.
- When present, the hooks behave exactly as today.

**Key interfaces:** `handshake_result` (`engine.rs`), the handshake result handling in `installEngine`
(`plugin/src/plugin.js`), `compactionParams`, the two compaction handlers, `plugin/tests/harness/bridge.mjs`'s
stub hello, `tests/fixtures/bridge/hello-response.json`.

**Acceptance criteria:**
- [ ] `hello` carries `capabilities.compaction: true`; the frozen fixture is updated and its schema test is green.
- [ ] A stub without the capability produces **no** compaction `inject` on the wire, leaves `output.context`
      unchanged, never calls `session.prompt`, and emits one log line.
- [ ] A stub with the capability exercises both hooks exactly as today (the existing compaction suites stay green).
- [ ] The wrapper's no-op is pinned by a test that fails if it appends the chat block instead.
- [ ] No new dependency; production panic-free.

**Out of scope:** raising `MIN_PROTOCOL` (it refuses every pre-33 engine and invalidates every fixture pinned
to `1.0.0`); issue 67's V2 first-class compaction hook; the double-count fix itself (issue 33's).
