## What

The fleet scratch root moved from `<repo>/tmp/` to `<repo>/.tmp/` on 2026-10-22. Five of the root
package's integration tests were migrated; **three were not**, and they still create their scratch trees
under the legacy `<repo>/tmp/scratch`:

| file | site | builds |
| --- | --- | --- |
| `tests/production_api_wiring.rs` | `scratch_dir` (`:92-105`) | `current_dir()/tmp/scratch/production-api-wiring/<prefix>-<pid>-<nanos>-<serial>` |
| `tests/skills_live_wiring.rs` | `scratch_dir` (`:43-56`) | `current_dir()/tmp/scratch/skills-live-wiring/…` |
| `tests/web_dist_wiring.rs` | `scratch_dir` (`:47-60`) | `current_dir()/tmp/scratch/web-dist-wiring/…` |

Three others already use the current root and prove the intended shape: `tests/engine_shutdown.rs:598`
(`stage_scratch_root`), `tests/logging_composition_wiring.rs:48` (`scratch_dir`), and
`tests/web_dist_packaging.rs:87` (`scratch_root`, via `CARGO_MANIFEST_DIR`).

`tests/web_dist_packaging.rs:26-28` documents the divergence by name — it says it chose
`CARGO_MANIFEST_DIR/.tmp/…` "over `<repo>/tmp/scratch` (where `tests/web_dist_wiring.rs:47-59` writes
`tmp/scratch/web-dist-wiring`) so this shard adds no second scratch root of its own". So the drift was
known and deliberately left; this issue owns it. That paragraph becomes obsolete when the three sites move.

## Evidence (MEASURED, 2026-10-29)

- A single `cargo test --workspace` run wrote **721 files** into `<repo>/tmp/` at 06:55 (the overnight
  gate run), on top of the pre-existing tree.
- The legacy tree was then removed by hand: **5,380 files / 121 MB / 3,291 dirs** (`find tmp -depth -delete`).
  That cleanup is **not durable** — the next workspace run rebuilds the directory.
- `.gitignore` carries both `/tmp/` (line 5) and `/.tmp/` (line 6), so neither location is ever visible to
  `git status`; nothing detects the drift.
- `tmp` was a **real directory**, not the `tmp -> .tmp` compatibility symlink the fleet scratch-root rule
  describes, so the legacy path never resolved into `.tmp/` here.

## Why it matters

1. **The cleanup is one run from undone.** The tree reappears after every `cargo test --workspace`.
2. **Collision hazard.** If the documented compatibility symlink `tmp -> .tmp` is ever restored, these
   three tests start writing their 5,000-file scratch trees into `.tmp/scratch` — the directory that holds
   the fleet's blueprints' probes and search digests. They are namespaced subdirectories, so it is
   pollution rather than corruption, but it defeats the point of the relocation.
3. **Two roots in one suite** is a split brain: the same test package writes under `tmp/` and `.tmp/`
   depending on which file you look at.

1. `tests/production_api_wiring.rs:101` — `.join("tmp")` → `.join(".tmp")`.

5. `tests/web_dist_wiring.rs` — six sentinel paths `Path::new("tmp/scratch/unused-exe")` (`:278`, `:294`,
   `:317`, `:426`, `:446`, `:461`). They never need to exist (they feed a negative resolution case), so

Prefer `.join(".tmp")` over `CARGO_MANIFEST_DIR/.tmp` for these three unless there is a reason to change
their base: they deliberately use `current_dir()` so the path is absolute at test time, and
`web_dist_wiring.rs:43-46` explains why (`resolve` must not reinterpret the fixture path relative to a
pretend cwd).
