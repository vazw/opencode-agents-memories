One restart carried three landed-but-inactive changes: the zstd-bumped engine (issue 116), the wrapper's
engine-stderr drain (issue 117) and the Thaw wave-1 web UI (issue 118, which was already staged and needs
no restart). This file records what was **measured after** the restart, because "deployed" and "works" are
different claims.

## The drain's first live proof (issue 117)

`~/.opencode-mem/opencode-mem.log` holds **three** session starts — `11:38:24`, `16:21:13`, `19:59:17` —
and across the whole file:

```
startup_tick     1
decay_tick       1
```

Both occur **once, at 19:59:17**, in the first ~300 ms of the new session:

```
[2026-11-03T19:59:17.701+07:00] consolidation.startup_tick: {"busy":0,"component":"consolidation","failed":0,"level":"info","projects_scanned":12,"runs":12}
[2026-11-03T19:59:17.773+07:00] profile.decay_tick: {"component":"profile","level":"info","profiles_scanned":2,"profiles_updated":2}
```

The 16:21 session ran the same engine family on the same store and produced **neither** line, which is the
discriminating half: those events were being written to fd 2 and discarded, and the only thing that changed
between 16:21 and 19:59 is the wrapper. `grep -c engine.stderr_dropped` is **0**, so the 256-line bounded
queue never overflowed either.

Caveat, stated rather than glossed: this proves the drain **renders events that were previously lost**. It
does not yet prove the retry/dead-letter strings specifically — `capture.retry_scheduled` and `dead_letter`
are both **0**, because no capture has retried or exhausted since the restart. Those two counters are the
open observability claim, and they can only be closed by a real retry happening.

  `["aria-label"]`, colon-named attributes in the document **0**, `html` background
  `rgb(20, 23, 28)`.

## What would have falsified it

A running exe hash equal to `d6223037…` (host not actually restarted, or the wrapper spawning a stale
path); `consolidation.startup_tick` appearing in the 16:21 session (meaning the log always had it and the
drain is not the variable); `engine.stderr_dropped` non-zero (the queue overflowing under normal load); or
`user_version` changed (a schema migration nobody declared).
