**Rule (pinned)**: before a divergent loser is discarded, every INBOUND foreign-key reference to the discarded row's identity **within the same database** is REPARENTED — the referencing column is rewritten to the KEPT row's value for that column — and each affected reference is recorded in the sidecar (below). **The reference set is DERIVED, never hardcoded**: for every table in the database, `PRAGMA foreign_key_list(<child table>)` names the parent table, the child column (`from`) and the parent column (`to`); a reference is in scope when its parent table is the table holding the divergent group. SQLite foreign keys are intra-database by construction, so “same database” is satisfied by the pragma's own row, and the rule is not `agent_sessions`-specific. **Only references that would OTHERWISE DANGLE are rewritten**: if a surviving parent row still matches the discarded row's values on the referenced column set, the child is already resolved and is left byte-untouched — no line, no count. ## D. Embedding compatibility strategy

### D.1 Memory shards (fingerprints EXIST — preserve and require equality)

Three-part evidence rule, all evaluated on the staged clone before merge writes:

- **E1 (build continuity)**: consolidating build's resolved fingerprint == fingerprint evidenced for the live engine from snapshot config evidence (item 12). Mismatch → refusal (exit 73): cross-build embedding rewrites are unsupported.

- **E3 (facts)**: `facts.db` absent (fail-closed §C.5) — no episodic-style rule needed for it in this wave.

A kernel lock dies with its process, so it cannot go stale and does not contradict the reservation's no-auto-reclaim rule; it serializes custodians only and fences no engine (the §E.2 TOCTOU residual and Q9 are unchanged). When (3)'s abort happens while it DOES hold that fd — the normal pre-`Prepared` abort syseng S3 closed — it runs the in-process adopt below on the SAME retained descriptor: no second acquisition, no `EWOULDBLOCK`, no misclassification.
