### Shared experiment contract and boundedness
`Case` is a fixed enum for the named experiments, not arbitrary SQL/path input. `Observation` contains `case`, `status: pass|fail|unknown`, `schema`, `row_differences`, `duplicate_occurrences`, `barrier_observations`, `duration_ms`, `limitations`, `artifact_paths`; errors are containment, conflict, unsupported schema/encoding or engine failure, never silent skips. Preserve Turso value types; compare blobs as bytes and NULL as NULL; floating bytes are not normalized through JSON.

Contract: input is synthetic, closed immutable baseline and explicit association map; successful copy preserves all non-association typed values; any unsupported binding or divergent ID returns before copying. During preflight scan, `seen` contains all previously examined IDs and their complete comparison values; the source remains immutable. During copy, the destination contains exactly the approved first k unique rows, and only after complete preflight. Each loop increases k through a fixed fixture list; no retry loop is unbounded. Zero rows is an explicit no-op; singleton/all-equal duplicate inputs retain one; reverse order gives identical logical output. Each concurrency wait is bounded at 10 seconds, child lifetime at 30 seconds; timeout is INCONCLUSIVE with retained evidence, never success. Keep fixture under 100 rows per DB and <= 8 vector dimensions; one full measurement suite, no load benchmark campaign. Unsupported dimensions/nonfinite vectors are recorded engine limits, not coerced. SHA-256 may use existing system `sha256sum` under syseng, not a new library.

### A/B and inverted-world ruling
- **A: future offline maintenance design.** Pros: finite custody and no active cached handles during replacement. Cons: downtime, cross-DB restore protocol still required. Prediction: shared blob/oracle and owned-child restore pass. Refutation: reproducible loss or inability to restore/reopen synthetic tuples using actual Turso. This wave does NOT measure graceful shutdown of the live service or prove full-root production recovery.
- **B: future online integrated design using existing barriers.** Pros: could avoid downtime and reuse caller interfaces. Cons: requires proven admission/drain across all stores and caches. Prediction: currently traced barriers cover all relevant admission and already-admitted work. Refutation: a real relevant interface completes unsafe work under the supposed barrier, or a traced caller bypasses it. Busy counts and zero errors in a small run alone neither prove nor disprove a correct future online redesign.
- **A wins (bounded feasibility recommendation only):** shared preservation and restore pass, and an actual barrier bypass refutes B's existing-barrier premise. Recommend A for subsequent design/syseng gate because future downtime is accepted; do not claim smaller implementation from unbuilt code.
- **B wins (bounded feasibility recommendation only):** A has a measured A-specific failure while B prerequisites, including drain and handle lifecycle, are actually demonstrated with no unknown paths. Shared raw-copy failure cannot by itself make B win. No B win based on 'downtime unacceptable': that contradicts the recorded user policy.
- **NEITHER:** a shared prerequisite fails in both drafts as specified (for example raw blobs cannot be copied/queryable with required exact preservation), or the measurement disproves any need for the proposed mechanism. State the precise falsified premise; do not infer all possible consolidation designs are impossible.
- **INCONCLUSIVE / no discriminator:** missing schemas/episodic encoding, unexercised admission paths, unavailable toolchain, nondeterministic interruption, or both candidates' prerequisites pass without separating evidence. Both feasible is not automatic A win; offline preference may be an explicit policy recommendation, not a measured victory. Changed-seam counts are READ inventories; implementation size/effort remains INFERRED, with later implementation needed to settle it.
- **Inverted world:** if source tracing shows an existing lossless mechanism already satisfies all measured requirements, report that and close as measurement, not a new deliverable. If retained constraints eliminate any authorized consolidation, stop without inventing work. Even a positive result cannot unblock Phase C: production design, auxiliary blockers, syseng gate and separate cutover approval remain mandatory.
