`~/.opencode-mem/*.json*` carries no `inject_on` override (grep: absent), so the live engine advertises
`"first"`. In `first` mode the turn-0 block is cached and replayed by the `context` hook (`adapter.js:86-89`)

at `adapter.js:122` says so explicitly ("retain context until policy refresh/cleanup").

## Consequence for issue 149 — recorded, not fixed here

149's Decision 2 ("restore on the next prompt; no new trigger") is **false as the tree stands**: there is no
next-prompt refresh to ride, so a `## Recent actions` section would be captured, stored, and then never
delivered to the one child it exists for. The block a compacted child receives in `first` mode is its turn-0
block, replayed.

Forced repair: invalidate the cached block at compaction so the next prompt is a refreshing turn — one line in
the `compaction` hook, where `event?.sessionID` is already read (`adapter.js:97-113`, `:102`). Pinned contracts
are unaffected: `v2-plugin-adapter.test.mjs:178` ("a session with no cached injection gets nothing") and `:397`
("cleanup drops the cached block") both describe an *empty* cache, which is what invalidation produces.

The inverted world: if after that line lands a post-compaction turn still logs no `inject.requested`, the
`context`-hook replay (not the refresh path) is what a child actually sees, and the section belongs on the
compaction leg instead.
